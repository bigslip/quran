# Phase 5 Auth & Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ensure the custom authentication stack (Email + Social) and backend synchronization logic are fully tested, accessible, and compliant with the project's WAI-ARIA and DLS primitive standards. Since significant components already exist, this phase focuses on rigorous test coverage, robust edge-case handling, and strict component API compliance.

**Architecture:** The auth components are located in `src/components/Login` and `src/pages/login.tsx` (and related auth pages). Hook and API logic are in `src/hooks/auth` and `src/utils/auth`.

## Global Constraints
- Tests must pass in Vitest (`yarn vitest run <file>`).
- Subagents must write tests *before* writing or modifying component logic (TDD).
- WAI-ARIA guidelines must be respected (e.g., `aria-invalid`, `aria-describedby`, focus management, ARIA live regions for errors).
- DLS primitives (Skeleton, Spinner) should be used for loading states where appropriate.
- Containers and form components must spread `React.HTMLAttributes` to support wrapper injections.
- All sync hooks must handle Redux-persist rehydration gracefully.
